# Release Notes - Version 8.0.63

**Release Date:** 2026-08-17

## Overview

`mcli ci preflight` now serialises its `act` runs machine-wide. Sixteen repos on
this machine carry the pre-push hook; concurrent pushes started concurrent `act`
runs against the *same* container runtime (one podman VM, fixed CPU/memory), and
the host starved — an Android emulator under test ANR'd while the runs churned,
and stopping podman was futile because each new push restarted it within seconds.

## Changes

- **New `mcli.workflow.ci.act_lock`** — a machine-wide `fcntl.flock` on
  `~/.mcli/locks/ci-act.lock`. `preflight` takes it before running `act`, so
  concurrent invocations queue instead of piling onto the container runtime.
- **Bounded wait.** 600s by default; configurable per-invocation with
  `mcli ci preflight --lock-timeout SECONDS` or machine-wide via
  `MCLI_CI_LOCK_TIMEOUT`. `MCLI_CI_LOCK_PATH` relocates the lockfile (tests).
- **Never blocks a push.** On timeout the gate reports the existing
  "cannot validate" state (exit `2`, or `3` where an online runner can validate)
  with a loud message, instead of either hanging or starting the second
  concurrent container run the lock exists to prevent.
- **No stale locks.** `flock` is owned by the open file description, so the
  kernel releases it on normal exit, on exception, and on `SIGKILL`. The
  `pid=… repo=…` line written into the lockfile is informational only — it feeds
  the "waiting for…" message and is never consulted for correctness.
- **Fails open, never blocks.** If the lockfile itself cannot be created or
  opened (read-only home, owned by another user, full disk), `preflight` warns
  and runs `act` unserialised — the pre-8.0.63 behaviour — instead of raising.
  An exception there would have exited `1`, the one code every pre-push hook
  blocks on, wedging pushes machine-wide over an unrelated filesystem problem.
- **Scope.** Only the `act` path is locked. The `make ci-native` gate is
  host-local (no container runtime) and stays unlocked; the capability probe
  runs before the wait, so a dead Docker is still UNREACHABLE immediately rather
  than after 600s.

## Exit-code contract

Unchanged — `0=pass, 1=fail, 2=cannot validate, 3=use runner`. Sixteen pre-push
hooks branch on these values. A lock timeout maps onto the existing
UNREACHABLE path; no new exit code was introduced.

## Validation

- New `tests/unit/workflow/test_ci_act_lock.py` (14 tests): two concurrent
  processes' critical sections are asserted disjoint, three concurrent
  `preflight` calls are asserted to never overlap inside `run_act`, the timeout
  path returns without hanging, the lock survives an exception, and a
  `SIGKILL`ed holder does not wedge the next caller.
- Exit-code contract tests extended in `tests/unit/workflow/test_ci_cli.py`
  (`--lock-timeout` forwarding, default `None`).
- `tests/unit` suite: 1479 passed, 1 pre-existing environment-dependent failure
  (`test_ipns_manager.py::test_returns_none_when_unset`, which reads a real sync
  key present on the host — fails identically on `main`).

## Upgrade Guide

No action required. Nothing changes for a single push at a time; concurrent
pushes now queue and print which repo/PID they are waiting on.
